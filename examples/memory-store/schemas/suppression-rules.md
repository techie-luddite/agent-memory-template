# Suppression Rules

Suppression means a memory is retained but removed from default retrieval.

## Suppress when:
- the memory is stale but may still have audit value
- the memory has been superseded by a newer truth
- the memory is too noisy or low-signal for normal context injection
- the memory only applies to a past environment, workspace state, or task phase

## Suppressed memories should:
- remain indexed
- remain recoverable on strong trigger or explicit request
- not influence default context assembly

## Reactivation triggers

Reactivate or reconsider when:
- the user explicitly asks for historical context
- current observations conflict with active or durable memory
- an old environment, machine, or project mode becomes relevant again
